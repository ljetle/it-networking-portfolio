# Border Gateway Protocol (BGP) and Network Address Translation (NAT)

## Overview

This project demonstrates inter-domain routing and address translation in a multi-autonomous-system network using Cisco Packet Tracer. The network consists of three autonomous systems: AS1, AS20, and AS40. AS20 functions as the transit autonomous system connecting the other two.

The project focuses on configuring Border Gateway Protocol (BGP) to exchange routing information between autonomous systems and Network Address Translation (NAT) to allow internal hosts to communicate with external networks using translated addresses.

Routing tables, BGP neighbor information, ping tests, traceroutes, and NAT translation tables were used to verify network connectivity and observe how routing and address translation operate across the network.

## Objectives

- Configure a network containing multiple autonomous systems.
- Configure and verify OSPF for intra-domain routing.
- Configure BGP for inter-domain routing between autonomous systems.
- Examine routing table changes as routing information is learned.
- Compare the administrative distances of BGP and OSPF.
- Verify end-to-end connectivity using ping and traceroute.
- Configure and inspect NAT translations.
- Observe how internal addresses are translated when communicating with external networks.
- Compare NAT/PAT with Dynamic NAT.

## Technologies and Tools

- Cisco Packet Tracer
- Cisco IOS CLI
- Border Gateway Protocol (BGP)
- Open Shortest Path First (OSPF)
- Network Address Translation (NAT)
- Port Address Translation (PAT)
- Dynamic NAT
- Ping and traceroute
- Routing table and NAT translation verification

## Network Topology

The network consists of three autonomous systems:

- **AS1:** The originating autonomous system containing internal hosts.
- **AS20:** The transit autonomous system connecting AS1 and AS40.
- **AS40:** The destination autonomous system containing the external network and server.

OSPF provides intra-domain routing, while BGP exchanges routing information between autonomous systems. NAT translates internal addresses as traffic moves toward external networks.

## Routing Configuration and Verification

The `show ip route` command was used to inspect the routing tables and identify directly connected networks, OSPF-learned routes, and BGP-learned routes.

```text
show ip route
```

### Routing Table Entries

The routing tables contained several route types:

| Route Code | Meaning |
|---|---|
| `C` | Directly connected network |
| `O` | OSPF route |
| `O IA` | OSPF inter-area route |
| `B` | BGP route |

The routing table outputs demonstrated how routing information evolved as additional routing protocols were configured.

- Initially, routers had directly connected routes for their local interfaces.
- OSPF added routes learned within the internal routing domain.
- BGP introduced routes learned from other autonomous systems.

The Router 3 routing table included BGP-learned networks such as `165.13.51.16`, `165.13.51.24`, and `165.13.51.32`, along with OSPF routes for portions of the `192.168.51.0/24` address space.

## Administrative Distance

The routing table results showed the following administrative distances:

| Routing Protocol | Administrative Distance |
|---|---:|
| BGP (external) | 20 |
| OSPF | 110 |

Administrative distance is used by a router to compare the trustworthiness of route sources when multiple sources provide a route to the same destination. A lower administrative distance is preferred.

The recorded BGP administrative distance was 20, compared with 110 for OSPF.

## Connectivity Testing

Ping and traceroute were used to verify connectivity between hosts in different autonomous systems.

### Ping Testing

The ping test checked communication between PC0 and PC4, with the destination shown as `60.60.51.2`.

```text
ping 60.60.51.2
```

Successful communication demonstrated that packets could travel across the routed network to the destination.

### Traceroute Testing

The following command was used to observe the path taken by packets:

```text
tracert 60.60.51.2
```

The recorded path was:

1. `192.168.51.9`
2. `192.168.51.14`
3. `192.168.51.18`
4. `165.13.51.2`
5. `165.13.51.18`
6. `60.60.51.2`

The report describes the path as traveling through R1, R2, R3, R5, and R6 before reaching PC4.

Additional traceroute testing from PC2 showed a different path through the network, demonstrating that the path observed depends on the originating host and the available routing information.

## Network Address Translation (NAT)

NAT was used to translate internal host addresses when communicating with external networks.

The following command displayed the active translation entries on Router 3:

```text
show ip nat translations
```

The translation table showed inside and outside addresses, including the inside local, inside global, outside local, and outside global fields.

### NAT Translation Results

The report identified the following translation behavior:

- PC0's inside address was translated to `165.13.51.1` when communicating from AS1 toward AS20.
- When multiple computers in AS1 communicated with AS40, their translated addresses included `165.13.51.11` through `165.13.51.14`.

The translation output demonstrated how NAT maps internal host addresses to addresses used for communication outside the originating network.

### Understanding NAT Translation Fields

| Field | Description |
|---|---|
| Inside local | Address assigned to the internal host |
| Inside global | Address representing the internal host to external networks |
| Outside local | Address of the external destination as represented locally |
| Outside global | Address of the external destination on the outside network |

These fields help identify how source and destination addresses are represented on each side of a NAT boundary.

## NAT/PAT vs. Dynamic NAT

The lab compared NAT/PAT with Dynamic NAT.

| Feature | NAT/PAT | Dynamic NAT |
|---|---|---|
| Address translation | Multiple internal devices can share one public IP address by using different transport-layer port numbers | Internal devices are assigned addresses from a public address pool |
| Public address usage | Conserves public IPv4 addresses by allowing address sharing | Uses public addresses from the available pool |
| Translation behavior | Tracks connections or flows using address and port information | Maps internal addresses to available public addresses |

NAT/PAT allows multiple internal devices to share a single public IP address, while Dynamic NAT assigns internal devices public addresses from a pool.

## Key Takeaways

- OSPF provides intra-domain routing, while BGP exchanges routing information between autonomous systems.
- Routing tables change as routers learn directly connected, OSPF, and BGP routes.
- BGP and OSPF have different administrative distances, affecting route selection when competing routes are available.
- The `show ip bgp summary` command helps verify BGP neighbor relationships and received prefixes.
- Ping verifies reachability, while traceroute reveals the intermediate hops toward a destination.
- NAT translates internal addresses for communication with external networks.
- NAT translation tables show how inside and outside addresses are represented.
- NAT/PAT allows multiple internal devices to share one public IP address, while Dynamic NAT uses a pool of public addresses.

## Conclusion

This project provided practical experience configuring and analyzing inter-domain routing and address translation in Cisco Packet Tracer. By examining routing tables before and after configuration, the project demonstrated how directly connected routes, OSPF routes, and BGP routes contribute to network reachability across autonomous systems.

Connectivity tests verified communication between hosts, while traceroute revealed the paths packets followed through the network. NAT translation tables demonstrated how internal addresses were translated for external communication.

Overall, the project reinforced the roles of BGP, OSPF, and NAT in connecting separate networks and provided experience verifying routing behavior and address translation through Cisco IOS commands.
