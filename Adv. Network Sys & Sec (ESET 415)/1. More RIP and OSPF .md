# Routing Protocols: RIP and OSPF

## Overview
This lab focused on configuring and comparing Routing Information Protocol (RIP) and Open Shortest Path First (OSPF) using Cisco Packet Tracer and physical networking hardware.

We first created a network in Cisco Packet Tracer using RIP, then reconfigured the same topology to use OSPF. We verified connectivity between PCs and a web server using ping and HTTP tests. We then recreated the network using physical routers, a switch, and laptops to test routing behavior and observe how the network responds to a connection failure.

## Objectives
- Configure RIP routing in Cisco Packet Tracer.
- Configure OSPF routing and compare its behavior with RIP.
- Verify connectivity between hosts across multiple subnets.
- Test HTTP access to a web server.
- Configure routing protocols on physical network hardware.
- Use `ping` and `tracert` to troubleshoot connectivity.
- Observe route changes following a network link failure.
- Compare routing protocol convergence and fault tolerance.

### Router Connection Failure
We disconnected the connection between Router 0 and Router 1 to observe how the network responded.

Before the failure, traffic could travel directly from Router 0 to Router 1 and then reach the server. When that connection failed, the network used an alternate path through Router 2 to reach Router 1.

The updated traceroute showed the additional hops:

```text
Tracing route to JLT [170.1.1.2]
over a maximum of 30 hops:

  1     4 ms     4 ms     4 ms  10.1.1.4
  2     5 ms     6 ms     4 ms  200.1.2.2
  3     6 ms     9 ms     6 ms  200.1.3.2
  4     5 ms     6 ms     7 ms  JLT [170.1.1.2]

Trace complete.
```

The trace now showed four hops instead of three, indicating that traffic was taking an alternate route to reach the server.

### RIP vs. OSPF

| Feature | RIP | OSPF |
|---|---|---|
| Routing metric | Hop count | Cost, commonly based on interface bandwidth |
| Hop limitation | Maximum of 15 hops | No equivalent 15-hop limit |
| Routing approach | Distance-vector | Link-state |
| Route calculation | Selects routes based on hop count | Uses the shortest-path algorithm |
| Typical use | Smaller, simpler networks | Larger, more complex networks |

RIP is suitable for smaller networks where simple configuration is important. OSPF is better suited to larger networks because it uses link-state information and calculates routes using Dijkstra's shortest-path algorithm.

### Response to Link Failure
When the connection between Router 0 and Router 1 failed, traffic was redirected through Router 2 before reaching Router 1 and the server. The alternate path increased the number of hops to the destination, demonstrating how routing can adapt when a connection becomes unavailable.

## Key Takeaways
- RIP and OSPF both allow routers to exchange routing information and communicate across multiple subnets.
- RIP selects routes using hop count and is generally better suited to smaller networks.
- OSPF uses link-state information and shortest-path calculations, making it suitable for larger networks.
- Ping tests verify connectivity between hosts and servers.
- HTTP testing confirms that the web server is accessible through the network.
- Traceroute reveals the sequence of routers traffic traverses to reach a destination.
- OSPF can recalculate routes when a connection fails, helping maintain network connectivity through alternate paths.

## Conclusion
This lab demonstrated the configuration and practical behavior of RIP and OSPF through both simulation and physical hardware. Connectivity tests confirmed that hosts could communicate across subnets and access the web server using both routing protocols.

The link failure test demonstrated how routing can adapt when a connection becomes unavailable. The alternate path increased the number of hops to the destination, illustrating the importance of dynamic routing and network redundancy. Overall, the lab reinforced the differences between RIP and OSPF and showed why OSPF is often preferred for larger networks requiring scalability and fault tolerance.
