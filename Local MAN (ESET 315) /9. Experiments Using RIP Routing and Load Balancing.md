# Experiments Using RIP Routing and Load Balancing

## Overview
This lab focused on configuring RIP routing, assigning /30 subnets, analyzing routing tables, and observing network behavior during link failures. Two network topologies were constructed to test routing paths, RIP updates, and packet forwarding using Cisco IOS commands.

## Objectives
- Assign /30 subnets and configure router interfaces.
- Configure serial connections with a clock rate of 56000.
- Verify connectivity using `tracert`.
- Analyze routing tables using `show ip route`.
- Observe RIP updates using `debug ip rip`.
- Examine routing changes after a link failure.
- Monitor packet forwarding using `debug ip packet`.

## Key Takeaways
- `/30` subnets provide two usable IP addresses and are useful for point-to-point connections.
- `tracert` identifies the hops packets take between endpoints.
- `show ip route` displays the routes known to a router.
- `debug ip rip` helps monitor RIP routing updates.
- Link failures can change the routes used to reach a destination.
- `debug ip packet` provides visibility into packet forwarding and reception.
- Physical connection issues can prevent successful network testing.
